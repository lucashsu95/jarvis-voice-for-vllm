# JarvisVoice：三層架構

| 層 | 做什麼 | 狀態 |
|---|---|---|
| 第一層 | 語音輸入：自動收音 → 切句 → 轉寫 → 貼進游標所在的輸入框 | 完成 |
| 第二層 | 跟 Typeless 一樣：一段話講完，帶上下文交給 AI 整理、改寫再寫進去 | 完成 |
| 第三層 | 不用先點輸入框：是「要打的字」就自動找對的輸入框寫進去；是「指令」就直接操作 app | 完成 |

```
麥克風 → 本機切句（停 0.85 秒）→ 轉寫（gpt-transcribe＋專有名詞）
   │
   ├─ AI 整理關著：一句一句貼（第一層）
   │
   └─ AI 整理開著：停超過 1.8 秒算一段（第二層）
         │  讀上下文：app、視窗、網址、輸入框、游標前後、選取（AX 小幫手，約 7 ms）
         ▼
      AI 整理（OpenAI／DeepSeek／Claude 三選一）＋ Jev 判斷是不是指令（同時打，不多花時間）
         │
         ├─ 要打的字：游標在輸入框 → 寫進去
         │            游標不在輸入框 → Jev 挑視窗裡要寫的輸入框 → 對焦 → 寫進去（第三層・輸入）
         ├─ 選取了字又講「改正式一點」→ 改寫選取的字
         ├─ 「刪掉剛剛那句」「換回原文」→ 選回剛貼的字處理
         └─ 指令：Jev 每一步看畫面上的按鈕、連結、輸入框，決定點哪個、填哪裡、按 Enter、完成了沒（第三層・指令）
```

## Typeless 怎麼做（查證過的）

**官方說法**（[官網](https://www.typeless.com)、[隱私權政策](https://www.typeless.com/privacy)）：
- 語音和「有限的上下文，例如你正在用的 app，以及裡面相關的文字」，即時送到雲端處理後丟棄。
- 會把語音與相關文字送給第三方雲端 AI（Microsoft、Google），並宣稱對方也零保留。
- AI 層的功能：
  - 清理：只去贅字和結巴（髒話、刻意重複、招呼、一兩個字的回答都照留）；講到一半改口時只留最後的意思；把講出來的清單、步驟排成條列。只有整段都是語氣詞才不寫，模型還是把真的話整理成空的就照原稿寫。
  - 個人化：依 app 調整語氣（聊天輕鬆、email 正式、文件精簡）；個人字典可以自動學，也可以手動加。
  - 語言：支援 100 多種語言，可以混著講。
  - 選取文字後的操作：用講的改寫（變短、變正式）；對選取的文字提問（摘要、解釋、翻譯）。
  - 其他：邊講邊翻譯；歷史存在本機。

**反向工程的說法**（[競品 Voibe 的文章](https://www.getvoibe.com/resources/typeless-privacy-issues/)，未經證實）：Typeless 透過 macOS 的輔助使用 API 抓瀏覽器網址、焦點 app 名稱、視窗標題，也會要求螢幕錄影權限。

**歸納：** Typeless 就是「語音轉寫」加上「一層 LLM 編輯」。第二層照這個做；第三層（自動找輸入框、語音指令）是我們多做的。

## 第一層：語音輸入

`bin/listen.mjs`：ffmpeg 收音（24kHz）→ 本機判斷人聲、停 0.85 秒切一句 → 轉寫（OpenAI `gpt-transcribe` 帶專有名詞，也可以換 `local`、`parallelsandbox`）→ 轉台灣正體、套固定替換 → AX 小幫手確認游標在輸入框後貼上。

## 第二層：AI 整理（跟 Typeless 一樣）

1. **分段**：「句」停 0.85 秒切出來（停 0.4 秒就先送轉寫，見下面「延遲」）；「段」要每句都轉完、而且停夠久才算結束，或暫停、切到不收音的 app。講到一半改口要看整段才知道，所以整段一起整理。
   - 停多久算一段：字一回來就先整理，整理好時已經停了 `speed.pasteAfterMs`（預設 1.2 秒）就貼；整理途中又開口（或又多一句）就作廢，等整段講完一起整理。提早整理關掉（`speed.pasteAfterMs: 0`）時照舊要停滿 `ai.segmentPauseMs`（預設 1.8 秒）。
   - 跟以前唯一的差別：停 1.2～1.8 秒又接著講，以前併成一段，現在分成兩段各自貼。
2. **上下文**：開口時就由常駐的 AX 小幫手（`bin/ax-agent.js`）先讀好（講完直接用；貼上後丟掉，下次開口再讀），一次約 7 ms：
   - app 名稱、bundle id、視窗標題、網址（從網頁區塊的 `AXURL` 讀，不用「自動化」權限）。
   - 輸入框的角色、標籤（例如 Claude 的「Prompt」）、游標前後各 400 字、選取的字。
   - 視窗裡看得到的字（不含輸入框）最後約 1,500 字：網頁用 `AXStaticTextSearchKey`（只要看得到的），原生 app 走 AX 樹收 `AXStaticText`。Claude 視窗約 0.17 秒、Chrome 約 0.33 秒。AI 靠它判斷在討論什麼：實測畫面在講 JarvisVoice、原稿被聽成 JavaScript，三家都改回 JarvisVoice；「這段 JavaScript 的 map 要改成 forEach」三家都不改。
3. **AI 整理**（`bin/editor.mjs`）：系統訊息放固定規則和專有名詞（三家都會快取），使用者訊息放上下文和整段原稿。輸出 JSON `{ mode, text, goal, app }`：
   - `insert`：去贅字和結巴、改口只留結果、條列、換行、標點、台灣正體、保持原本語言（英文不會被翻成中文）、照專有名詞的寫法、配合游標前後（接半句不重複、後面有字不加句號）、依 app 或網站的語氣（`ai.styles`，內建聊天、email、給 AI 的指令、文件四種）。
   - `replace_selection`：有選取、講的是「改正式一點」「縮短」「翻成英文」→ 改寫選取的字（貼上就會取代選取）。
   - `delete_last`、`revert_last`：「刪掉剛剛那句」「換回原文」→ 小幫手確認游標前面正好是剛貼的字，用 AX 選起來換掉；對不上就不動。
   - `command`：開了語音指令才有，見第三層。
   - 原稿是問題或「忽略前面的規則」這類話，一樣只整理不回答。
4. **寫入**：貼上（暫存剪貼簿 → Cmd+V → 還原）。送按鍵前確認要寫的 app 真的在最前面，不然等一下再寫，不會打到別的 app。小幫手按完 Cmd+V 就回覆，等 app 讀剪貼簿、還原剪貼簿的 0.35 秒在回覆之後才做（字在按下 Cmd+V 時就出現了，下一個請求才要等）。
5. **換回原文**：選單「換回原文」或講「換回原文」，把上一段 AI 整理過的字換回轉寫原稿。
6. **詞彙表自動更新**（`bin/vocab-auto.mjs`）：每段寫完後，最多每 2 分鐘、畫面有變才請 AI 從畫面上的字挑出專有名詞當候選。
   - 候選要在 3 次不同的時候（相隔 10 分鐘以上）都看到，或使用者真的講到了（AI 整理後的字裡有它），才加進詞彙檔最後的「自動學到」區。
   - 上限：整張詞彙表 250 個、自動詞 80 個；滿了用分數挑一個拿掉（用到次數 × 10 ＋ 來源加分〔改字 30、講到 20、畫面 0〕− 多久沒用到的天數），新詞分數不夠高就不加。使用者自己寫的詞永遠不動。
   - 詞彙檔改了，轉寫和 AI 整理幾秒內就用新的；有句子還在轉寫時等轉完再換。
7. **自動學詞**：AI 整理過的字貼上後 30 秒內，每 3 秒讀一次那個輸入框；使用者自己改了字（不是只在後面多打），就請 AI 挑出被改正的專有名詞，加進詞彙檔的「自動學到」區。訊息送出、欄位清空時用最後一次看到的版本。
8. **歷史**：`~/.voice-dictation/history.jsonl`，只存在本機，超過 2 MB 換檔。
9. **失敗**：AI 逾時（6 秒）或回錯格式，貼原稿。

### 延遲

規劃與量測：`cubelv_docs/計劃/2026-10-19_JarvisVoice語音加速規劃.md`。原則是能先做的先做，猜錯就丟掉重來，整理的結果跟以前一樣（同樣的轉寫模型、整理規則與模型、指令判斷）：

| 做法 | 設定 | 省多少 |
|---|---|---|
| 停 0.4 秒就先把這句送去轉寫（`TurnSplitter` 的暫定斷句）；到 0.85 秒確定講完就用這份，中間又開口就作廢、照舊等整句 | `speed.earlyTranscribeMs` | 約 0.45 秒 |
| 字一回來就開始整理，整理好時已經停 1.2 秒就貼（上面「分段」） | `speed.pasteAfterMs` | 約 0.4 秒 |
| 開口時就讀好上下文（截圖認字的 app 要 1 秒）、游標不在輸入框時跟整理同時挑好要寫的框 | — | 0.05～1 秒 |
| 貼上：按完 Cmd+V 就回覆，不等還原剪貼簿 | — | 0.35 秒 |
| 轉寫、整理每次同時送兩份，誰先回用誰（`core/hedge.mjs`），砍掉偶爾 1 秒以上的那幾次 | `speed.hedge` | 尾巴 |
| 講話中先 HEAD 一下轉寫、AI、Jev 的網址，講完的請求不用重新握手 | `speed.warm` | 0.05～0.12 秒 |

每次貼上 log 記一行「速度：講完到貼上 X 秒（字回來、整理好、貼上各花多少）」，`history.jsonl` 也記 `latencyMs`。

**游標旁的小框**（`app/ui.js`，`listen.mjs` 送 `bubble` 事件）：開口就出現在游標下面（`context` 回的 `field.caret`：`AXBoundsForRange`，拿不到用輸入框；不在輸入框就放視窗下方中間），講話中顯示即時預覽（本機 SenseVoice 每多 0.5 秒聲音認一次目前這句，約 0.05～0.1 秒，轉台灣正體；只顯示不貼，雲端的字回來就換掉），接著「整理中」、「已貼上」（秒數只記在 log，不顯示）；指令顯示做到哪一步，沒貼上、出錯寫原因。無邊框、不會變成作用中的視窗、滑鼠點穿過去。

## 第三層：自動找輸入框、語音指令（用 Jev 決策）

[Jev](https://typesafe.ai) 是 TypeSafe 的 System One 決策模型：不寫字，只在給定的選項裡挑（choice）或回答是非的機率（noul），附信心。從台灣打一次約 0.2 秒，每百萬輸入 token US$0.042。第三層的每個決定都是「從畫面上現有的東西裡挑一個」，正好是它擅長的。沒有 Jev key 時，同樣的問題改問 AI 整理那家（約 1 秒）。

### 這段話是「要打的字」還是「指令」

- 游標不在輸入框：照 AI 整理的判斷，不問 Jev。對照實測 20 句各 2 次，只用 AI 40/40；以前要 Jev 也同意（機率 ≥ 0.5），反而把「幫我傳給媽媽說我晚點到」兩次都擋成打字，10/18 拿掉（`cubelv_docs/分析/2026-10-18_JarvisVoice_Jev必要性.md`）。
  - 只有一個單向的例外（10/19）：AI 說是打字、Jev 同時判斷是指令的機率 ≥ 0.95，就照「指令，……」再請 AI 拆一次。同一句「開啟我的 email」AI 有時判成打字，游標不在輸入框就被貼進這個視窗上次寫的地方（Threads 的發文框）。Jev 只能把打字升成指令，不會把 AI 的指令擋成打字。實測（Chrome 開著 Threads）：「開啟我的 email」「開啟我的 mail」「打開 YouTube」0.98、「看一下我的 mail」0.95，「這個按鈕太小了，幫我改大一點」0.89、「幫我查一下部署表」0.59、「明天下午四點開會」0.06 照樣打字。
- 要打開網站（例如「開啟我的 email」「打開 YouTube」）：AI 在 `text` 帶網址（沒講哪一家的 email 用 mail.google.com）。畫面上有直接的連結就點，沒有就在瀏覽器網址列填網址按 Enter。以前畫面上沒有 Gmail 入口（例如停在 Threads）就一定失敗；10/19 在另開的 Chrome 視窗從 Threads 實跑：填網址列 → Enter → 到 mail.google.com。
- 游標在輸入框（Claude、聊天 app 的游標幾乎都停在輸入框）：同時把畫面上的按鈕、連結列給 Jev，問兩題：是不是要操作畫面、講到畫面上哪一個。機率 ≥ 0.9，或 ≥ 0.75 而且講到畫面上的某個東西，就當指令，再請 AI 拆出目標和要搜尋的字。
  - Claude 視窗實測：「切到 JarvisVoice 那個 session」0.92、「打開設定」0.92、「回到 PM C」0.97（講到「PM C」）當指令；「我說切到某一些 session 它都不會切過去」0.03、「你切到另一個分支再跑一次測試」0.82（沒講到畫面上的東西）照樣打字。
- 游標在輸入框、AI 說是指令但 Jev 看了畫面說不是：當成要打的字。傳訊息給某人（AI 拆出了要寫的訊息）除外：Jev 只看畫面上的按鈕，傳訊息的對象不在畫面上，實測「幫我傳給媽媽說我晚點到」「跟 Jason 說我晚點到」在 LINE、Claude 各 2 次，8 次都被擋掉，10/18 改成照 AI。
- 開頭講「指令，……」不管游標在哪都當指令。
- 以前 Jev 的實測（10/17，現在游標不在輸入框時已經不問 Jev）6 句：「進到台積電的個股頁」0.99、「打開設定頁」1.00、「搜尋鴻海」0.81 判成指令；「幫我看一下台積電今天為什麼跌」（在 Claude 輸入框）、「明天下午三點開會記得帶筆電」、「好啊我晚點看一下」判成要打的字。

### 第三層・輸入：自動找輸入框（`autoFocus`）

游標不在輸入框時：
1. 小幫手列出視窗裡的輸入框：網頁和 Electron 用 `AXUIElementsForSearchPredicate`（Claude 視窗 12 ms），原生 app 走 AX 樹。
2. 只排掉寫不進去的（停用的、沒有大小的）；搜尋框、網址列都在候選裡。
3. 這個視窗上次寫的那個、或只剩一個 → 直接用。
4. 其他交給 Jev 挑；沒有決策器就照規則排第一的：標籤像訊息框、多行、越下面越大越好。
5. 設 `AXFocused` 對焦，重讀上下文，寫進去。

### 第三層・指令：直接操作 app（`commands`）

例如「進到台積電的個股頁」：
1. AI 拆出 `goal`（打開台積電（2330）的個股頁）、`text`（要填進搜尋框的「台積電」）、`app`（有講要切到哪個 app 才有）。
2. 每一步，小幫手列出畫面上可以操作的東西（按鈕、連結、輸入框、選單、分頁、清單列；Chrome 一頁約 70 個，100 ms）。
3. Jev 一次回答兩題：下一步做什麼（點／填字／按 Enter／完成／做不到）、對哪一個。
4. 程式照答案做：
   - 點：`AXPress`。
   - 填字：app 在最前面時全選後貼上；不在最前面時直接設值。
   - 按 Enter：app 在最前面時送 Enter；不在最前面時用 `AXConfirm`。
5. 等畫面 0.7 秒再做下一步，做到決策器說完成或做不到為止。
6. 停下來的情況：決策器信心太低（動作 < 0.3、對象 < 0.25），或按了「暫停收音」。
7. 實測（真的 Jev，測試用看盤視窗）：
   - 「打開台積電（2330）的個股頁」：填字 → Enter → 點「台積電 2330」→ 完成，4 次決策各 0.17–0.28 秒，共 3.3 秒。
   - 「打開設定頁」「回到首頁」：各 1.2 秒。

### 第三層・讀不到畫面的 app：截圖認字

LINE 這類 app 輔助使用只讀得到搜尋框和訊息框（實測 3 個元件、畫面上的字是空的）：
- 判斷：能操作的東西扣掉輸入框和視窗小按鈕少於 3 個、畫面上的字讀不到，才截圖；讀得到的 app 不截。
- 截最前面那個視窗（`CGWindowListCreateImage`，只在記憶體裡）→ macOS Vision 文字辨識（精準模式，快速模式認不出中文；LINE 視窗約 0.7–0.9 秒、70–80 段字）→ 圖片丟掉，只留字和位置。
- 認出來的字：當 AI 整理的畫面上下文；也當指令的選項（落在已經讀得到的元件裡的字不重複列，例如搜尋框裡打的字）。點的時候在字的正中間點滑鼠。
- 要「螢幕錄影」權限；沒有就提醒一次。
- 截圖認出來的畫面字多又有錯字，Jev 挑不準（實測一直點搜尋框），這種畫面的每一步改問 AI。

### 第三層・傳訊息給某人

「幫我傳給 BU 說你好」：AI 拆出對象（`text`）和內容（`message`），然後照固定步驟走，不讓決策器在畫面上自由點（實測在 LINE 自由點會點到對話標題、打開好友資料進入編輯）：
1. 每一步先問「現在打開的是不是和這個人的對話」（看對話標題；另一個名字裡剛好包含它、群組都不算）；是 → 寫進最下面的多行輸入框，結束，不送出。
2. 搜尋框裡還不是這個名字 → 填名字。
3. 搜尋框下面同一欄、第一個含這個名字的結果 → 點；等畫面換好最多確認 3 次；不是這個人就停，不試下一個。

在使用者的 LINE 實測：從別的群組出發，填「BU」→ 點「bubu」→ 確認 0.90 → 寫「你好」，5.3 秒；沒有送出。

## 共用核心（`core/`）：Mac 小程式、CubeLV、平行沙盒共用一份

上面這些規則（AI 整理的提示、Jev 的題目和門檻、指令的步驟、找輸入框、詞彙自動學），加上語音那一層（本機斷句、雲端即時轉寫的連線與重連補送、輸入框聽寫停下後怎麼寫回去），都放在 `core/`，只放和平台無關的邏輯：不用 `node:` 模組、不碰檔案（`tests/core.spec.mjs` 會檢查）。要看畫面、打模型、連轉寫、存東西，由呼叫端傳接頭進來；收音本身（Mac 的 ffmpeg、瀏覽器的 AudioWorklet）在各 app，每 100 ms 把一批樣本交給核心：

| 接頭 | 介面 | Mac 小程式怎麼接 | 其他 App 怎麼接 |
|---|---|---|---|
| 服務 | `complete({ system, user, schema })`、`jev({ state, questions })` | `core/providers.mjs` 的 `ownKeyService`：自己的 key 直接打 OpenAI／DeepSeek／Claude、TypeSafe | 接自己的後端（扣點數、平台吸收） |
| 畫面 | `elements({ limit, ocr })`、`act({ handle, action, text, x, y })` | AX 小幫手（`bin/ax-agent.js`）：輔助使用＋截圖認字 | 讀自己的頁面 |
| 存放 | `loadState`、`saveState`、`readVocab`、`writeVocab` | 檔案（`~/.voice-dictation`） | 瀏覽器的儲存或自己的後端 |
| 轉寫 | `connect()` → WebSocket 網址，或 `{ url, headers, sessionUpdate }` | `bin/engines/realtime.mjs`：OpenAI 直連（自己的 key）或平行沙盒 control（API key 換語音 token） | CubeLV 後端的 `/ws/transcription`、平行沙盒 control 的 `/v1/transcription` |

語音那一層的分工：

- `turns.mjs`：`AudioTurnDetector` 判斷有沒有人聲（門檻跟著最近 3 秒的底噪走，尖峰夠高也算），停頓 850 ms 切一句；`TurnSplitter` 再加上開口前 0.4 秒的預錄，回傳這批要送出去的聲音和切出來的句子，還有暫定斷句（停 400 ms 報 `tentative`、之後又開口報 `resumed`），呼叫端可以先送轉寫。
- `hedge.mjs`：同一個請求同時送幾份、誰先成功用誰，其他的取消；`ownKeyService` 的 `hedge` 選項用它。
- `transcription.mjs`：`createTranscriber` 是一條 OpenAI Realtime transcription 連線（每句一個 commit；連線前的聲音先排著；斷了就重連，把還沒拿到字的聲音與句子照順序重送；每句的字照講的順序、帶起訖時間）。Mac 小程式用 `lazy`（有聲音才連，安靜夠久先關）。`createSpeechTranscription` 是一段錄音（輸入框聽寫、驗收錄影的字幕）：斷句、時鐘校正、`hearing`／`recognizing` 狀態、checkpoint、finish。
- `dictation.mjs`：輸入框聽寫停下後的第二層與寫回：`polishTranscript`（整理、逾時照原稿）、`applyPolish`（寫成什麼、要不要送出、留不留換回原文）、`revertPolish`、`joinPolished`。

其他專案用 `scripts/sync-core.sh <目標資料夾>` 同步一份過去：每個檔案開頭寫來源 commit，不在那邊改；要改回 `core/` 改再同步。TypeScript 用 `core/index.d.mts` 的型別。

## 程式

| 檔案 | 做什麼 |
|---|---|
| `core/` | 共用核心：`hedge.mjs`（雙發）、`editor.mjs`（AI 整理）、`decide.mjs`（決策題目與門檻）、`commander.mjs`（指令步驟）、`targeter.mjs`、`learn.mjs`、`vocab.mjs`、`turns.mjs`（斷句）、`transcription.mjs`（即時轉寫連線）、`dictation.mjs`（輸入框聽寫的寫回）、`ocr.mjs`（截圖認字的字排順序、接成文字、跟其他上下文合在字數內）、`providers.mjs`（自己的 key）、`index.d.mts`（型別） |
| `bin/listen.mjs` | 常駐程式：收音、切句、分段、讀上下文、AI 整理、找輸入框、指令、寫入、換回原文、自動學詞 |

| `bin/history.mjs` | 本機歷史 |
| `app/ui.js` | 選單：AI 整理三選一、自動找輸入框、語音指令、換回原文；選單列圖示；游標旁的小框 |
